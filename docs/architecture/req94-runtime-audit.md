## Operational implications

Existing coding runs need a complete approval-bound contract and explicit supported test IDs: `module/package/TestBusiness`, `test/business.test.ts`, or repository-qualified IDs such as `service::test/business.test.ts`. The primary verification command may remain the built-in multiline script. When it lacks structured evidence, the worker runs only the unresolved required tests through its trusted adapters within the remaining timeout. Free-form descriptions, unsupported runners and independent no-change proofs remain blocked. The broader FAIL/BLOCKED items above still prevent a claim of unrestricted multi-provider acceptance.
