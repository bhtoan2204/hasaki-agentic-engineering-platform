## Remaining limits

- Executable required-test adapters support native Node test files and Go module/package test IDs. Other frameworks are rejected before approval when identified; no generic shell command is accepted from plan output. Planned files must exist and be executable by the supported runner at verification time.
- `NO_CHANGE_REQUIRED` still requires independent requirement-satisfaction evidence that this executor cannot establish. It remains a visible failure rather than an unverified success.
- An explicitly enabled trusted-operator policy still runs without OS mount isolation when bubblewrap is unavailable. Bubblewrap uses the existing platform mount/network policy; this work does not claim a new hostile-code confidentiality or network boundary. Live self-development, remote service tests and provider credentials still require their existing deployment policies.
- npm readiness remains the existing package-manager scope. This change does not introduce pnpm/yarn installation adapters, an authenticated package registry, or a signed software-supply-chain attestation.
- Provider integrations are hermetic CLI/MCP fixtures; no paid live-model benchmark or external pull-request publication is claimed. No deployment, application database migration, merge or automatic merge was performed.
